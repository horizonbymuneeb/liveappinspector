# Report schema (`liveappinspector.report/v1`)

One acquisition produces one JSON document. It is self-describing: `schema`
identifies the contract, `tool` records who collected it and with what, and every
artifact section carries a `meta` block that says how the collection went.

- Machine-readable structure: [`schema/report-v1.schema.json`](../schema/report-v1.schema.json)
  (JSON Schema 2020-12, generated by `scripts/gen-schema.py` from a real capture)
- Field-by-field provenance and caveats: [FORENSIC_NOTES.md](FORENSIC_NOTES.md)
- Sealing and verification: [CHAIN_OF_CUSTODY.md](CHAIN_OF_CUSTODY.md)

```bash
lai inspect --pid 1234 --json report.json          # acquire
lai verify report.json                             # recompute the seal
```

## Top level

| Field | Type | Meaning |
|---|---|---|
| `schema` | string | always `liveappinspector.report/v1` |
| `tool` | object | engine name/version/build profile/arch, OS, host identity, elevation state, `dpi_awareness`, start/end timestamps, duration |
| `case` | object | `case_id`, `examiner`, `organization`, `notes` — copied from the CLI / dashboard |
| `selection` | object | how the target was chosen (`interactive_pick`, `hotkey_pick`, `explicit_pid`, `explicit_hwnd`, `foreground_window`), click point, `hwnd`, and the `window` facts |
| `process` | object | Module A — identity, architecture, times, memory, protection level, launch context (command line, cwd, environment) with a `*_source` for each |
| `user_context` | object | Module B — account/SID/integrity/elevation/session/token, `privileges[]`, `groups[]` |
| `genealogy` | object | Module C — `parent`, `ancestors[]`, `children[]`, `descendants[]` |
| `network` | object | Module D — `connections[]` with protocol/endpoints/state, plus counts |
| `modules` | object | Module E — `items[]` (name, path, base, size, version resources, `missing_on_disk`) |
| `handles` | object | Module E — `items[]` (handle, type, classifier, object name, access, `target_pid`) and `counts_by_type[]` |
| `registry` | object | Module E — `keys[]` held open, `autoruns[]` referencing the image, scan notes |
| `services` | object | Module E — `services[]` from the SCM (hosted by or registered to this image) |
| `binary` | object | Module F — SHA-256, NTFS identity, PE facts, Authenticode/catalog trust, hashing metadata |
| `integrity` | object | seal, custody log, section health, warnings |

## `meta` — present on every section

```json
{
  "status": "ok | partial | denied | error | skipped | timeout",
  "error": "Win32/NT reason when access was refused or a collector failed",
  "win32_error": 5,
  "collected_at_utc": "2026-11-01T15:52:17.629831Z",
  "warnings": ["collector-specific observations"]
}
```

`status` is the field to branch on in automation. A section is **never** empty
without a reason: `denied` means the OS refused, `partial` means something was
truncated or unresolvable, `skipped` means it was disabled by flags or is not
applicable. Treat "absent artifact" as indistinguishable from "clean" only when
`status` is `ok`.

## Conventions

- **Time** — every timestamp is UTC RFC 3339 with microsecond precision
  (`2026-11-01T15:52:17.629831Z`). Process creation time is additionally given as
  `created_unix_ms` and the raw FILETIME (`created_filetime_raw`) so it can be
  traced without float rounding.
- **Provenance is explicit.** Fields whose source matters carry a sibling
  `*_source` string: `process.image_path_source` (live handle vs kernel table vs
  name search), `process.command_line_source` (live PEB vs CIM fallback),
  `binary.signature.signature_source` (`embedded` vs `catalog`). Never present a
  fallback value as if it were authoritative.
- **Hashes** — lower-case hex, no separators. `binary.sha256` is the file on disk
  at collection time; `integrity.report_sha256` is the seal over this document.
- **Empty vs unavailable.** `""` means "collected but empty"; `null`/absent means
  "not available, see `meta`". `handles.object_address` is usually absent because
  Windows 11 redacts kernel object pointers from unprivileged callers.
- **Unknown fields must be ignored.** Within schema `v1`, new optional fields may
  appear at any level; consumers must not reject a report for containing them.

## Versioning policy

| Change | Action |
|---|---|
| New optional field, new section-level `warnings[]` entry, new enum value in `status` | same schema version (additive) |
| Renaming, removing or changing the meaning/units of an existing field | bump `schema` to `/v2`; keep a reader for v1 for at least one minor release |
| New section | same schema version; document it here and in `docs/FORENSIC_NOTES.md` |

`lai verify` parses the document against `model.rs`; it tolerates a UTF-8 BOM and
ignores unknown fields, so a v1 report stays verifiable by later builds.

## Consuming a report

```bash
# every section that did not collect cleanly
jq -r 'to_entries[] | select(.value.meta?) | select(.value.meta.status != "ok")
       | "\(.key): \(.value.meta.status) \(.value.meta.error // "")"' report.json

# established endpoints with reverse DNS
jq -r '.network.connections[] | select(.state=="ESTABLISHED")
       | "\(.remote_address):\(.remote_port) \(.remote_hostname // "-")"' report.json

# unsigned modules that are also missing on disk (hollowing indicator)
jq -r '.modules.items[] | select(.missing_on_disk) | .path' report.json

# custody timeline
jq -r '.integrity.custody_log[] | "\(.seq) \(.at_utc) \(.action) \(.detail)"' report.json
```

In Python:

```python
import json, jsonschema
report = json.load(open("report.json", encoding="utf-8-sig"))
jsonschema.validate(report, json.load(open("schema/report-v1.schema.json")))
assert report["schema"] == "liveappinspector.report/v1"
```

## Interpretation warnings baked into the format

These are recorded as data, not prose, so they survive an export:

- `genealogy.meta.warnings` may carry a **PPID-recycling** finding (a parent that
  started after its child cannot be the real launcher).
- `binary.meta.warnings` may carry a **deterministic-timestamp** note (Microsoft
  `/Brepro` stamps look like the future and are not timestomping) or a
  **hash-mismatch** note when the file changed between the two read passes.
- `handles.meta.warnings` may carry an **unresolved-object-type** note (duplication
  refused; run elevated for full handle semantics).
- `network.meta.warnings` may carry a **bounds** note when reverse DNS hit its
  per-lookup budget.
